# rtl/eth — the Ethernet layer

Everything between the fibre and the first fabric flip-flop of the fast path.
One 10GbE port per `eth_10g_wrapper` instance; `fpga_top.sv` builds three
(market-data A, market-data B, order entry).

## 2. ⚠️ The cut-through / FCS contract

**This is the single most important thing in this directory.**

The Ethernet FCS is the last four bytes of the frame. A cut-through MAC has
already handed every payload byte downstream by the time it learns whether those
bytes were valid.

```
t=0                                         t=end      t=end+4B
|------- payload streamed to the parser ----|--- FCS ---|
                                             ^
     the book may already be updated here    you learn it was corrupt here
```

**`mac_rx` forwards first and judges afterwards.** The contract:

1. **There is no `tready` anywhere on the RX path.** Downstream must accept every
   beat, unconditionally, the cycle it is offered. This is CLAUDE.md §5 rule 4.
2. **`m_axis_tuser` is valid only on the beat where `m_axis_tlast` is high.** On
   every other beat it is driven 0 and means nothing.
3. **`m_axis_tuser == 1` at `tlast` means the whole frame is bad.** Everything
   downstream was given for that frame must be treated as never having happened.
   It covers FCS mismatch, runt, oversize, XGMII `/E/`, malformed preamble and
   misaligned start — one verdict, one meaning.
4. **Polarity is normalized here.** AMD's 10G/25G Ethernet Subsystem drives
   `rx_axis_tuser` *low* on `tlast` for a bad frame (PG210). Nothing downstream
   of `rtl/eth/` ever sees that convention; it is `1 == bad`, everywhere.

### What the rest of the design owes this layer

Speculative forwarding is only sound if someone can unwind. Per
[02-networking/01-ethernet-phy-mac.md §6](../../manuals/02-networking/01-ethernet-phy-mac.md):

1. the feed handler decodes speculatively, tagging updates with a frame id;
2. book updates are journaled so one frame can be rolled back;
3. the strategy may fire and the order encoder may fully build the outbound frame;
4. **⚠️ the order gateway must not put the first byte of an order on the wire
   until the commit for the frame that produced it.** This layer supplies that
   commit/abort as `tlast` + `tuser`. It is the only hard interlock, and it is
   cheap — the verdict lands ~4 bytes (3.2 ns) after the last payload byte, and
   for any message that is not the last in the datagram it has already happened
   by the time the strategy fires;
5. on abort: roll back, count `rx_fcs_error`, and treat the frame as a MoldUDP64
   sequence hole.

> ⚠️ **A speculative design with no commit gate is a working-but-wrong design.**
> It passes every clean-pcap test, runs for months in colo, and then sends a real
> order derived from a corrupted frame the first time an optic degrades. The
> failure is rare, silent and expensive — exactly the shape this project exists
> to eliminate.

### Why store-and-forward is rejected

Buffer the frame, check the FCS, then release: downstream needs no unwind logic
at all. The cost is one full frame serialization time, **always**, on the happy
path — at 10G, 0.8 ns/byte:

| Frame | Store-and-forward penalty |
| --- | --- |
| 64 B | 51 ns |
| 100 B (typical MoldUDP64/ITCH packet) | 80 ns |
| 512 B | 410 ns |
| **1500 B** | **1200 ns** |
| 9000 B (jumbo) | 7200 ns |

The 1500 B row alone consumes the entire sub-1 µs wire-to-wire budget. It is
nevertheless implemented behind `mac_rx`'s `STORE_AND_FORWARD` parameter
(default `0`) so the trade-off can be *measured* rather than argued about.
⚠️ Setting it to `1` on a live link is a latency regression of up to 1.2 µs.

## 3. ⚠️ RX never backpressures — it drops and counts

CLAUDE.md §5 rule 4. There is no `tready` into the MAC RX, and no flow control on
the link in either direction. When the RX FIFO cannot take a frame:

- **Admission control.** A frame is admitted at its *first* beat, and only if
  `wr_almost_full` is low. `ALMOST_FULL_LEVEL` is set so the remaining headroom
  exceeds one maximum-length frame (191 beats at 1522 B), so an admitted frame
  always fits even if the core never reads. A refused frame is discarded whole —
  never partially forwarded — and `frames_dropped` increments once.
- **Mid-frame overflow** (unreachable if the threshold is honoured, and asserted
  against in simulation). The wrapper stops writing and, at the first cycle with
  room, injects one synthetic beat with `tlast=1, tuser=1`. Downstream still sees
  a well-formed stream where every frame ends with `tlast`, and the truncated
  frame is explicitly marked bad. **Correctness does not depend on the threshold;
  only the drop rate does.**

> ⚠️ Dropping is a design behaviour, not an error path to be "fixed" with flow
> control. A PAUSE frame at 10G can stall you for up to 3.36 ms — an eternity of
> lost ticks — and asserting PAUSE on a multicast feed port creates head-of-line
> blocking for everyone behind it, including you. Frames with EtherType `0x8808`
> are dropped and counted, never acted on.
>
> A non-zero drop count on a healthy 10G link means a downstream block is not
> keeping up. That is a design bug to find, not to throttle away.

## 4. Latency budget owned by this layer

Booked against the table in the `fpga_top.sv` header. 156.25 MHz, 6.4 ns/cycle.
**Every figure is a TARGET until a wire-to-wire measurement replaces it**
([05-optimization/04-measurement-and-profiling.md](../../manuals/05-optimization/04-measurement-and-profiling.md)).

| Stage | cyc | ns | fixed? |
| --- | ---: | ---: | --- |
| **RX** optics + GT PMA/PCS, elastic buffer bypassed (hard IP) | – | ~90.0 | fixed |
| **RX** `mac_rx` cut-through | 2 | 12.8 | fixed |
| **RX** `async_fifo` rx_clk → core_clk (2 sync + 1 read) | 3 | 19.2 | fixed |
| **RX wire → `m_axis`** | | **~122** | |
| **TX** `s_axis` → `async_fifo` → skid | 4 | 25.6 | fixed |
| **TX** `mac_tx` cut-through (`tvalid` → preamble on XGMII) | 2 | 12.8 | fixed |
| **TX** GT PCS/PMA + optics (hard IP) | – | ~90.0 | fixed |
| **TX `s_axis` → wire** | | **~128** | |

`fpga_top.sv`'s budget books `MAC RX (cut-through) 2 cyc` and
`MAC TX (cut-through) 2 cyc`; both are met exactly. The async FIFOs are the extra
5 fabric cycles this layer costs on top of those lines.

Notes on the numbers:

- **The two async FIFOs are not optional.** `rx_clk` is the recovered clock and
  has no defined relationship to `core_clk`. The only way to remove them is to
  run the entire fast path on the recovered clock, which breaks the moment the
  link drops. Don't.
- **`mac_rx` is 2 cycles, not 3,** because the end-of-frame lookahead needed to
  place `tkeep`/`tlast` is taken from the *unregistered* XGMII bus. The CRC is
  arranged so exactly one combinational CRC step is ever on that path, never two.
- **⚠️ Record the real GT/PCS numbers.** The ~90 ns figures are planning numbers
  from the manual, not datasheet numbers. Take the configured latency from the
  Vivado GT wizard report for the exact configuration, put it in the
  `eth_10g_wrapper.sv` header and in `docs/`, and update it whenever anyone
  re-runs the wizard
  ([02-networking/01-ethernet-phy-mac.md §9 rule 7](../../manuals/02-networking/01-ethernet-phy-mac.md)).
- **Serialization is the floor under all of it.** 0.8 ns/byte at 10G. You cannot
  react to a field before it has arrived.

## 5. `stat[4]` telemetry mapping

`core_clk` domain, free-running, cleared by `core_rst`. Consumed by
`telemetry.sv` through `fpga_top`'s `md_mac_stat` / `oe_mac_stat`.
CLAUDE.md §5 rule 7: every drop, error and rejected frame is counted.

| Word | Field | Meaning |
| --- | --- | --- |
| `stat[0]` | `frames_ok` [31:0] | RX frames delivered to `core_clk` with `tuser == 0`. |
| `stat[1]` | `frames_dropped` [31:0] | RX frames that **never reached `core_clk`**: FIFO admission refusal, mid-frame overflow, store-and-forward buffer overflow. Should be 0 forever. |
| `stat[2]` | `fcs_errors` [31:0] | RX frames delivered with `tuser == 1` — FCS mismatch, runt, oversize, XGMII `/E/`, malformed preamble, misaligned start. ⚠️ Alarm on **any** non-zero rate; a healthy 10G link shows zero for days. |
| `stat[3]` | `fifo_high_water` | packed: `[15:0]` RX FIFO occupancy high-water mark (sticky); `[23:16]` TX underrun count (saturating); `[31:24]` TX deliberate-abort count (saturating). |

32-bit counters **wrap** — the host differences successive reads. The 8-bit
sub-fields **saturate** instead, because a wrapped error counter reads as
"healthy", which is the worst possible failure mode here.

## 6. ⚠️ The `abort` input on `mac_tx`

`mac_tx` implements deliberate FCS corruption: XOR the computed CRC with
`0xFFFF_FFFF` before appending, so a frame already in flight reaches the peer
looking structurally normal and fails its FCS check. Required by the speculative
transmission optimization in
[01-fpga-design/02-pipelining-and-parallelism.md §5](../../manuals/01-fpga-design/02-pipelining-and-parallelism.md).

> ⚠️ **Using this in production requires written venue approval.** Deliberately
> invalid frames count against the exchange's link error-rate policy; enough of
> them and the venue may alarm, throttle or disconnect the session. Confirm in
> writing with the venue and the colo provider before any build that can assert
> this signal reaches a live session.
>
> ⚠️ **An aborted order is not a cancelled order.** You do not know whether the
> venue's receiver committed part of it downstream. Treat every abort as an
> *unknown-state* order and reconcile it on the slow path. Designing so that
> aborts never happen — risk checks complete before the first byte leaves — is
> strictly better than relying on abort.

**It is currently tied to `1'b0`** inside `eth_10g_wrapper`, because
`fpga_top.sv` is the port contract and carries no abort input. Exposing it is a
deliberate, reviewed change: add the port here *and* in `fpga_top.sv`, wire it
from `order_gateway`, and only after the venue confirmation above.

## 7. Build and simulation

- **`SIMULATION` defined** → `gt_wrapper_stub.sv`, a behavioural model. The whole
  design elaborates and runs under Verilator with no vendor IP. The stub defaults
  to internal XGMII loopback, so `mac_tx` → `mac_rx` is a zero-effort end-to-end
  self test of preamble / pad / CRC / IFG / terminate handling, and of the abort
  path. Direct XGMII injection and error injection are available through the
  public variables documented in the stub's header.
- **`SIMULATION` not defined** → `gt_wrapper.sv`, the Vivado-generated GT/PCS
  shim. That file must be generated before synthesis; it is a build artifact and
  is deliberately not source in this directory.

> ⚠️ **The stub ties `rx_clk` and `tx_clk` to `core_clk`, so the design is
> single-clock in simulation and the CDC is NOT stressed.** Zero ppm offset, no
> phase relationship risk. Per
> [00-foundations/04-clocking-reset-and-cdc.md §6](../../manuals/00-foundations/04-clocking-reset-and-cdc.md),
> CDC needs its own verification: structural CDC lint (`report_cdc`) on every
> build, treated as errors, plus the `async_fifo` testbench run at several clock
> ratios including nearly-equal frequencies. A passing simulation here is *not*
> evidence that the MAC boundary crossing is sound.

Other things simulation here cannot tell you: block lock, gearbox behaviour, the
1-in-33 gearbox stall under sustained load, eye margin, FEC mode mismatch, or
anything about a real link. See
[01-fpga-design/04-io-transceivers-and-serdes.md §9](../../manuals/01-fpga-design/04-io-transceivers-and-serdes.md)
for the hardware bring-up order (IBERT before MAC, PRBS31 zero-error soak, eye
scan recorded with the build).

## 8. Link configuration rules (all of them, non-negotiable)

From [02-networking/01-ethernet-phy-mac.md §9](../../manuals/02-networking/01-ethernet-phy-mac.md)
and [01-fpga-design/04-io-transceivers-and-serdes.md §11](../../manuals/01-fpga-design/04-io-transceivers-and-serdes.md):

1. 10GbE, **no FEC**, MTU 1500, fixed speed, **no auto-negotiation, no flow
   control**, on every link carrying market data or orders.
2. **Cut-through MAC only.** Store-and-forward anywhere on the fast path is a bug.
3. RX `tready` into the feed handler is tied high. Overload → drop and count.
4. Speculative RX processing is permitted; **unguarded order emission is not**.
5. Every rejected, errored, dropped, aborted, oversize and undersize frame is
   counted per port, with sticky error bits *and* transition counters — a link
   that flaps for 40 µs at 09:31 leaves no trace in a level-only register.
6. The vendor MAC/PCS is wrapped here and only here.
7. The configured GT/PCS/MAC latency is recorded in the module header and `docs/`.
8. **Never shorten the preamble or the IFG.** `mac_tx`'s `IFG_BEATS=2` puts ≥24
   idle bytes between `/T/` and the next `/S/` against a 12-byte requirement.
   The nanoseconds are not worth a conformance failure at the venue.
9. GT reference clock from a dedicated low-jitter source through dedicated pins —
   ⚠️ **never from an MMCM/PLL or fabric routing.**
10. RX and TX quads in the **same SLR**, and the whole fast path pinned into that
    SLR with a `pblock`. An SLR crossing on the hot path costs a Laguna register
    stage minimum.

## 9. Assumptions this layer makes, written down

| Assumption | Where enforced | If violated |
| --- | --- | --- |
| `/S/` only ever appears in XGMII lane 0 | realignment in `gt_wrapper` / stub; `mac_rx` detects and counts violations | frames dropped, `stat[2]` climbs, `a_start_lane0` fires in sim |
| RX FIFO headroom above `ALMOST_FULL_LEVEL` exceeds one max frame | `localparam` + elaboration `$fatal` in `eth_10g_wrapper` | mid-frame overflow path activates; frames dropped but never corrupted |
| The core accepts every RX beat, always | no `tready` exists to violate it; `a_rx_never_blocks` | design does not compile the mistake |
| TX source supplies beats contiguously once a frame starts | `TX_PREFILL` + 8-beat skid; `mac_tx` aborts and counts on underrun | frame goes out with a corrupted FCS, `stat[3][23:16]` climbs, `a_no_underrun` fires |
| `tkeep` is contiguous from lane 0 | asserted on both MAC interfaces | assertion failure in sim |
| CRC-32 reflected residue is `0xDEBB20E3` | `crc32_eth` self-check at elaboration, incl. proof it equals `bitrev(0xC704DD7B)` | `$fatal` at time 0 |
